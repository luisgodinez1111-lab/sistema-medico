# Evidence Report — GUX-001 (primer Golden UX Loop)

> Autoridad: `docs/design-contract/` (subordinada a V2.0.1/V2.1.1/Companion/Registry y al Design System v3.2).
> Ley de evidencia: SOURCE ≠ EXECUTED_MODEL ≠ EXECUTED_RUNTIME ≠ HUMAN_APPROVED. Gate por defecto: PENDING_EVIDENCE.

## Loop
GUX-001 — Resultado crítico → Obligación → Bloqueo de firma → **blocker exacto** → resolución autoritativa
**con evidencia** → refresh de readiness → Firma → auditoría/timeline.

## Mapeo al backend ya construido (runtime real)
- Bloqueo de firma: `clinical-runtime.countOpenCriticalResults` en el gate de firma del encuentro (Zero-Lost-Follow-Up).
- Resultado crítico: `result-lifecycle` (RECEIVE deriva `critical` de `classifyLab`; valor de pánico K⁺ 7.0).
- Resolución con evidencia: `result-lifecycle` cierre exige evidencia no vacía; obligación → COMPLETED.
- Firma: `encounter-lifecycle` (PROPOSED→…→SIGNED) tras readiness = 0 críticos abiertos.
- Auditoría: cadena `audit_chain_v3`; provenance y hashes en el timeline.

## Autoridad / clases epistémicas
- Resultado = FACT (fuente laboratorio, verificado). Obligación = estado accionable con owner + evidencia de cierre.
- Firma = acción de ALTO impacto (C5), autoridad HUMANA. Identidad = parcial/temporal (UNKNOWN ≠ normal).

## Estados enumerados (máquina de estados del gate)
BLOCKED → RESOLVING (pendiente) → READY → SIGNING (pendiente) → SIGNED (inmutable).

## Estados prohibidos vigilados (contracts/forbidden-states.ts)
`assertNoForbidden` en runtime + diseño: CRITICAL_OPEN+SIGN_READY (firma deshabilitada con crítico abierto),
RESOLVED_OBLIGATION+NO_RESOLUTION_EVIDENCE (cierre exige evidencia), ACKNOWLEDGED+IMPLIED_RESOLVED
("solo reconocer" NO cierra), UNKNOWN_COMMIT_STATE+SUCCESS (pendiente ≠ éxito), DRAFT+SIGNED_STYLE
(el borrador no se estiliza como firmado hasta la confirmación).

## Contratos de diseño aplicados
- Tokens verbatim (`design/tokens.ts`), tipografía Inter + `tabular-nums`, motion 120/180/240ms, reduced-motion.
- App-shell: nav 72/240, workspace fluido, rail 360; patient header con P0/P1/P2 SIEMPRE visible (incl. durante C5).
- Estado codificado en **forma + ícono + texto**, nunca solo color (semántica no-color).
- Fixture adversario `fixtures/adversarial/extreme-patient.json`: nombre largo, DOB parcial, identidad temporal,
  3 críticos (1 bloqueante), banner degradado (IA/red/proyección) persistente.
- Responsive: desktop → tablet (rail abajo) → mobile (IA transform); acción primaria y estado crítico persisten.
